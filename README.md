# Уголки — Vue 3 + Three.js

Перенос одностраничной игры «Уголки 3D» (`../ugolki3d.html`) в SPA на **Vue 3 + Vite + TypeScript**
со слойной архитектурой: правила не знают ни про Vue, ни про Three.js, рендер не знает правил игры,
а тяжёлый поиск ИИ вынесен в web-worker.

## Запуск

```bash
npm install        # или pnpm install
npm run dev        # дев-сервер Vite
npm run build      # typecheck (vue-tsc) + production build
npm run preview    # превью собранной версии
npm test           # unit-тесты ядра (vitest)
npm run typecheck  # только проверка типов
```

### Правила зависимостей

- `core` не импортирует ничего из приложения (тестируется в node, работает в worker).
- `engine` зависит только от `core`.
- `game` зависит от `core` + `engine` + `stores/composables`, **не** от `three` и Vue-компонентов.
- `three/BoardScene` зависит только от `core` (типы координат), не от Vue.
- `components/*` — единственное место, где Vue; `TheBoard.vue` соединяет `game` и `BoardScene`.

### Ключевые решения

- **Коммит модели после анимации**: `playMove` применяет ход к снапшоту, ждёт
  `animator.animateMove()` и только потом публикует доску — watcher сцены не
  «телепортирует» шашку в конец маршрута.
- **Эпоха сессии**: `newGame`/`undo` инкрементируют счётчик; анимация и поиск ИИ
  отменяют коммит, если партия уже перезапущена (в оригинальном коде это было гонкой).
- **Воркер вместо blob-workera**: `new Worker(new URL(...), { type: 'module' })` —
  Vite бандлит воркер с настоящим импортом ядра; при недоступности воркера
  движок деградирует в синхронный расчёт с микрозадачей.
- **Порт правил 1-в-1**: генерация ходов, эвристика, уровни и лимит 260 полуходов
  соответствуют оригиналу; поведение покрыто тестами (`npm test`).

## Публикация на GitHub Pages

Сборка использует **относительный base** (`base: './'` в `vite.config.ts`), поэтому
сайт работает по любому пути: и в корне (`user.github.io`), и в подпапке
(`user.github.io/ugolki-vue/`), и на кастомном домене — пересобирать под путь не нужно.
Воркер движка подгружается относительно своего модуля через `import.meta.url`,
`public/.nojekyll` отключает Jekyll.

### Вариант 1 — автоматика (рекомендуется)

В репозитории лежит готовый workflow [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml):
при пуше в `main` он ставит зависимости, прогоняет typecheck и тесты, собирает `dist/`
и публикует на Pages.

1. Заведите репозиторий с содержимым этой папки в корне.
2. В настройках репозитория: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. pushed в `main` — сайт опубликован (вкладка Actions покажет ссылку).

### Вариант 2 — вручную

```bash
pnpm run build
# содержимое dist/ — статика: загрузите её в ветку gh-pages
# или в /docs существующей ветки (Pages → From branch)
```

Локально собранную папку можно проверить так: `pnpm run preview`.
Открывать `dist/index.html` двойным кликом (file://) нельзя — браузеры блокируют ES-модули с диска.

## Отличия от оригинала

- Смена первого хода после каждой партии сохранена (`firstMove`), но при «Ещё раз»
  из модалки итога первым снова ходит тот, чей черёд по очерёдности.
- Модалка итога закрывается по Esc (в оригинале — только кнопкой/оверлеем).
